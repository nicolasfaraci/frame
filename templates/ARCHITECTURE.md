## Code organization and conventions

Rules must be concrete and checkable. Mark a rule `To be defined` rather than inventing it.

- **Structure**: directory layout, modules, and boundaries.
- **Naming**: files, directories, classes, functions, variables, and constants, by kind (for example camelCase, PascalCase, kebab-case, snake_case).
- **Granularity**: for example one class or component per file, maximum responsibilities per module.
- **Dependencies**: allowed direction between layers and modules, and what is forbidden.
- **Tests**: location, naming, and expected level of coverage.
- **Other rules**: error handling, logging, formatting and lint tooling.
